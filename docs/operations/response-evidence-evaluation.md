# 回答展示：技术对照与待安排的真人验收

默认展示来源记录、SAGE 已记录的缺依据问题片段和真实操作状态；研究身份补充来源/推论边界；有预约、建议或后台任务时才展示对应操作状态。完整执行图置于高级详情，仍保留真实路线、失败和重试，不改变后端权限和执行。

覆盖结果直接投影 `sage.runtime.evidence_coverage.missing_question_spans` 的已校验回执，随原回答持久化；不重新评价，不截断问题片段，不把模型辅助匹配当独立事实核验。旧数据没有回执时保持未知，不回填成功。前端身份强调只用已验证账号的资料，不用访客自选身份授权。

## 可重复的技术对照

运行 `node tools/compare_response_evidence.cjs /absolute/output/directory`，用静态服务器在本机打开生成的 `index.html`。

三种实验展示条件：A 仅答案、B 完整图与后台记录、C 分层依据。六个合成案例分别覆盖缺依据、有来源但未独立核验、预约待确认、后台失败、未执行建议、历史未知。每个案例三个条件使用同一答案、同一夹具输入；`comparison.json` 保留答案 SHA-256 和技术断言。图的 B 条件是完整图实验条件，不声称逐像素复刻旧生产 UI。

自动断言只能证明状态提示存在、答案没有变化、来源/操作边界没有被错误抹掉，不能证明用户理解更好、任务更快、信任更合理。功能回归另核对持久化、历史恢复、真实流式问答、滚动、引用和导出。

## 已知边界

真实缺依据验收中，带具体测量数值的事实查询正确显示了两项来源缺口，但现有任务识别还额外生成了研究实验建议。这些内容已明确标为候选建议、并非现有测量事实；本次展示对照不修改任务识别或重写答案。该现象不能算高质量回答的通过样本，也不能以来源卡或绿色节点掩盖，后续需单独验收事实查询与研究建议的意图区分。

## 真人验收：按用户要求待安排

不能由模型代答。不要现在招募或发送邀请。无遥测、不采集个人资料；主持人离线记录匿名编号和作答。入口支持 `?condition=A`、B、C；条件名称不解释优劣，避免诱导。

预先固定六案例的正确判分依据。按匿名编号轮换 ABC/BCA/CAB 顺序，轮换案例到条件的分配，避免同一人对同一案例重复作答造成记忆效应。正式运行前主持人保存分配表；不能把任意切换条件的技术浏览当盲测。

每案例记录：是否正确识别依据缺口/状态（主指标）、是否错误接受未核验事实或未完成操作、从看到问题到作答的用时、查阅详情次数。主观美观/满意度只能列为次指标。报告每条件人数、案例数、逐项错误率和不确定性；样本不足时只报告探索结果，不宣称有效提升。当前没有任何真人结果。
