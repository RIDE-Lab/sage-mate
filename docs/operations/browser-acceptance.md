# 公网浏览器验收：避免控制超时被误判成页面故障

浏览器控制、页面交付和后台执行分别验收；任何一个 HTTP 200 都不能替代真实页面观察。

## 2026-10-19 复现结果

- 同一内置浏览器：空白页 DOM 约 0.03 秒，截图约 0.02 秒；公网主页字体状态 `loaded`、DOM 可读。
- 公网主页单独截图实际 **30.13 秒**后成功返回真实图像，超过控制 REPL 的默认 30 秒期限。此前把截图期限设成 20/30 秒，会在结果返回前中断并重置控制句柄，制造后续绑定/读取失败。
- 给单次截图 45 秒执行期限，成功获取真实截图；健康页截图 12.65 秒也成功。新标签页导航和 DOM 操作亦成功。这个期限是验收控制操作的期限，不是延长用户请求、改变模型预算或掩盖回答超时。
- 应用日志出现过缺少浏览器路由、旧 webContents 销毁、调试监听器注销。仅凭 `client-new-thread` 别名不能判定根因：后来成功页面使用同一别名。不得宣称已修复应用内部路由代码。
- 仍未证明截图底层为什么耗时 30 秒；不把控制操作耗时当作模型回答时间，也不凭这种耗时更改网站鉴权/CSP、代理或永久关闭动画。

## 可复现的操作约束

1. 已知失败后先读当前标签清单。旧标签消失时，沿用当前浏览器绑定，创建新标签；不要循环重绑失效句柄。
2. 分开执行导航、DOM、点击与截图，每一步有独立结果；不要把多个可能各花十余秒的动作装进默认 30 秒调用。
3. 截图和点击分别单独给予 45 秒控制期限（不超过 60 秒）；不添加 sleep，不修改页面来制造静态通过。短 DOM 检查使用文档支持的有界读取。实测公网单次点击 30.41 秒、DOM 观察也可能约 30 秒；把填写和点击合并，即使给 45 秒仍会超时。必须真正拆开，而不是只提高一次总期限。
4. 导航成功不算验收：实际提问，观察完成答案、依据缺口、来源展开、历史恢复和工作流折叠。保留原始问题，不用换题回避缺口。
5. 若在该期限内仍失败，记录具体操作与实际结果，并保留未通过状态；切换 Chrome 只是另一条独立证据，不算内置浏览器已修复。

本记录修正验收操作的超时/句柄恢复方式，不包含修改 Codex 安装包或绕过电脑控制安全限制的操作。

## 新发布版本的实际公网验收

`112e924` 上线后，内置浏览器完成原始 9973 条研究问题的事实查询：页面显示 32.0 秒，保留准确率和测量条件两项原始缺口，无实验建议；来源入口实际展开，完整工作流默认折叠。后台同请求为 completed/stop，实际没有执行 `plan-experiments`，来源块与 canonical answer 一致。

因此“控制调用被默认期限截断”的操作故障已有可复现恢复方式；底层控制服务为何对公网动作等待约 30 秒仍未被证明或消除。原生 macOS Chrome 控制另出现 timeoutReached，未拿它冒充内置浏览器验收，也未修改安装包。不能将这次结果表述成“所有浏览器接口永久无延迟/不会再超时”。
