# Sage Mate 4.7.0

日期：2026-09-03。此版本汇总 4.6 系列近期问答、引用和交互改进；应用版本不代表推理引擎或模型的版本。

## 主要变化

- 完整回答：区分每项限制与整篇限制；深度及显式结构化问题使用可配置完整性预算。`finish_reason=length` 不作为完成结果缓存，修复失败时明确说明，避免以通用模板冒充成功回答。
- 真实 Support：普通 SAGE 工作流与技能问答保留可追溯知识来源；排除用途不符的材料，长文提供相关正文片段；没有可引用来源时明确提示。
- 交互：整合日夜主题、深度思考状态、排队/超时提示与取消恢复；移动端引用卡支持长文件名换行，并为固定输入区预留空间。
- 运行时身份：继续分别显示兼容基座、源码版本/SHA 和镜像身份，不用应用版本概括整个推理栈。本次发布不改变模型、设备映射或图模式配置。

## 验收与边界

问答修复的 305 项相关测试通过，15 项可选模型/夹具测试跳过；针对性公网普通、深度、取消恢复与 Support 检查见 [详细验收记录](../answer-grounding-2026-09-03.md)。这不等于所有问题均已正确，也不宣称偶发公网超时已消除。

源码 `__version__`、`pyproject.toml`、`uv.lock` 与发布种子 `changelog.json` 必须一致。新增的 `tests/test_release_version.py` 在普通测试流程中检查该契约。发布时还需更新已安装的应用包元数据，仅修改源码不能更新 `importlib.metadata.version("sage-mate")`。

## 已有部署升级

1. 保留本地配置、私有运行数据和未提交修改；检查是否有正在进行的聊天。
2. 同步本次应用代码，使用部署的 Python 解释器更新应用包（不解析或升级推理依赖）。
3. 通过 `tools/lib/runtime_seed.sh` 的发布种子流程同步版本日志；事先确认运行目录中的日志没有独立修改。日志是发布数据，不将其它私有数据同步到公开仓库。
4. 仅重载应用服务，检查 `/healthz`、`/health` 的 `app_version`、`/changelog`、包元数据以及页面页脚版本。无需重启引擎或代理。

本说明对应源码与站点发布，不表示 GitHub Release 中已上传 4.7.0 安装器；安装器和二进制附件需经过各平台构建验收后单独发布。
